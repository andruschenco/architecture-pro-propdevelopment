## Задание 1. Разработка проверочного листа по безопасности данных (PropDevelopment)

### Шаг 1. Классификация данных по ISO/IEC 27001/27002

На основе описания IT-ландшафта PropDevelopment выделены следующие типы данных и их категории.

| Категория            | Примеры данных                                                                                                                                                                                                                                                                                                                                                                                                                                     | Обоснование                                                                                                                                                                              |
|----------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **Публичные**        | – Описание жилых комплексов (планировки, фото)<br>– Цены на квартиры<br>– Новости компании<br>– Контактная информация компании                                                                                                                                                                                                                                                                                                                     | Данные размещены на открытой витрине, не содержат персональной или коммерческой тайны, доступны неограниченному кругу лиц.                                                               |
| **Внутренние**       | – Внутренние отчёты по продажам (без ПДн)<br>– Логи работы систем (без чувствительных данных)<br>– Метрики производительности серверов<br>– Организационная структура<br>– Внутренние инструкции для сотрудников                                                                                                                                                                                                                                   | Данные предназначены только для сотрудников компании. Их разглашение не нанесёт прямого ущерба клиентам или бизнесу, но может раскрыть внутренние процессы.                              |
| **Конфиденциальные** | – Персональные данные клиентов и собственников (ФИО, телефон, email, адрес, паспортные данные, СНИЛС, ИНН)<br>– Данные о бронировании и онлайн-турах<br>– Данные онлайн-сделок (включая интеграцию с госорганами)<br>– Платёжные данные (банковские карты, счета)<br>– Данные «Умного дома» (коды доступа, логи управления)<br>– Контракты API с партнёрами (содержат ПДн)<br>– Коммерческая тайна (условия сделок, ценообразование для партнёров) | Это информация ограниченного доступа, защищённая законодательством о персональных данных (152-ФЗ) и коммерческой тайне. Утечка или искажение наносят прямой ущерб клиентам и компании.   |
| **Секретные**        | – Ключи шифрования (TLS, данных)<br>– Учётные записи администраторов ЦОД и облачных сервисов<br>– Схемы внутренней сети и настройки межсетевых экранов<br>– Полные дампы БД с ПДн (необезличенные)<br>– Данные интеграции с госорганами (криптоключи, сертификаты)<br>– Политики безопасности и планы реагирования на инциденты                                                                                                                    | Утечка или потеря этих данных приводит к катастрофическим последствиям: компрометация всей инфраструктуры, невозможность восстановления, массовая утечка ПДн, уголовная ответственность. |

### Шаг 2. Определение рисков и их оценка

Для каждой категории выделены наиболее актуальные риски (по шкале: **незначительный** / **значительный** / **критический**).

| Категория            | Риск                  | Оценка             | Почему актуален                                                                                                                                                                                      |
|----------------------|-----------------------|--------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **Публичные**        | Искажение данных      | **Значительный**   | Неверные цены или характеристики на витрине приведут к недоверию клиентов, потере продаж, возможным судебным искам. Утечка данных не страшна, потеря не критична (данные можно восстановить из CMS). |
| **Внутренние**       | Потеря данных         | **Незначительный** | Логи и внутренние отчёты могут потребоваться для аудита или расследования инцидентов, но при наличии резервного копирования восстановление возможно. Прямого ущерба клиентам нет.                    |
| **Конфиденциальные** | Утечка данных         | **Критический**    | Уже есть жалобы клиентов на отображение чужих ФИО – это прямая утечка ПДн. Нарушает 152-ФЗ, грозит штрафами до 500 тыс. руб. (а при повторном – до 1 млн) и репутационным ущербом.                   |
|                      | Искажение данных      | **Критический**    | Ошибки в бронировании, статусе сделки, остатках квартир или показаниях счётчиков приводят к финансовым потерям, срыву сделок, судебным искам.                                                        |
|                      | Некачественные данные | **Значительный**   | Дублирование записей о клиентах из-за нескольких точек регистрации вызывает ошибки в личном кабинете (жалобы клиентов) и мешает построению аналитики.                                                |
|                      | Потеря данных         | **Критический**    | Утрата персональных данных или истории сделок из-за отсутствия бэкапов делает невозможным восстановление бизнес-процессов, влечёт штрафы и уголовную ответственность.                                |
| **Секретные**        | Утечка данных         | **Критический**    | Компрометация ключей шифрования, административных доступов или схем сети даёт злоумышленникам полный контроль над всей IT-инфраструктурой, включая базы ПДн.                                         |
|                      | Потеря данных         | **Критический**    | Без резервных копий секретных данных (например, ключей доступа к облачным ресурсам) восстановление работы после сбоя или атаки становится невозможным.                                               |

### Шаг 3. Mindmap (Визуализация результатов анализа в виде mindmap)

[Визуализация](data-security-mindmap.drawio)

Ниже приведена структура для создания **mindmap** в draw.io в текстовом виде. 

```
Безопасность данных
│
├── Публичные данные
│   ├── Описание ЖК, цены, новости
│   │   └── Риск: Искажение данных [Значительный]
│   │       └── Почему: неверные цены → потеря продаж, иски
│
├── Внутренние данные
│   ├── Логи, отчёты, метрики
│   │   └── Риск: Потеря данных [Незначительный]
│   │       └── Почему: есть резервное копирование, ущерб не критичен
│
├── Конфиденциальные данные
│   ├── ПДн клиентов (ФИО, тел., адрес, паспорт)
│   │   └── Риск: Утечка [Критический]
│   │       └── Почему: нарушение 152-ФЗ, штрафы, жалобы клиентов
│   ├── Данные бронирования и сделок
│   │   └── Риск: Искажение [Критический]
│   │       └── Почему: финансовые потери, срыв сделок
│   ├── Данные «Умного дома» (коды, ключи)
│   │   └── Риск: Утечка [Критический]
│   │       └── Почему: несанкционированный доступ в квартиры
│   ├── Платёжные данные (карты, счета)
│   │   └── Риск: Утечка [Критический]
│   │       └── Почему: мошенничество, PCI DSS, уголовная ответственность
│   └── Дубликаты клиентов (некачественные данные)
│       └── Риск: Некачественные данные [Значительный]
│           └── Почему: ошибки в личном кабинете, недовольство клиентов
│
└── Секретные данные
    ├── Ключи шифрования, доступы к ЦОД
    │   └── Риск: Утечка [Критический]
    │       └── Почему: полная компрометация инфраструктуры
    ├── Дампы БД с ПДн (необезличенные)
    │   └── Риск: Утечка [Критический]
    │       └── Почему: массовый слив персональных данных
    └── Схемы сети, конфигурации firewall
        └── Риск: Потеря [Критический]
            └── Почему: невозможно восстановить безопасность после атаки
```
